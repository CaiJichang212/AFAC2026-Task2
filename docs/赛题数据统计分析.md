# 赛题数据统计分析

## 1. 可执行结论

- 本次纳入训练集与 A 榜共 300 张图片，其中 long 类 150 张，table 类 150 张。
- 超过 FinixDoc-VL 约 16M 单图像素预算的图片有 220 张，超过 100M 像素的极端图片有 97 张，整图直传不是可行默认策略。
- 按当前 `configs/default.yaml` 中 `chunk.max_chunk_pixels=4M` 粗估，300 张图至少需要 5,970 个切片；如果按 16M 硬预算粗估，也至少需要 1,488 个切片。
- 最大像素样本为 `a4924b6d-2eb6-4ebc-828e-ee32475c9e3e.jpg`，约 386.57M 像素；最大长宽比样本为 `624fb24a-832f-4a79-8c3a-1cddbd0afde3.jpg`，长宽比约 127.72。
- 策略上应把 long 和 table 分开调参：long 优先保证纵向覆盖、接缝去重和标题连续性；table 优先控制二维切块、表头重复和 HTML 表格合法性。

## 4. 训练集与 A榜分布对比

A榜每类 50 张，训练集每类 100 张，目录结构和类别划分一致，适合用训练集先调参再迁移到 A榜。需要注意的是，迁移不能依赖文件名，只能依赖尺寸、长宽比、投影密度、表格线密度等可解释特征。

从统计指标看，重点比较三类差异：像素 P90 决定常规切块压力，最大值决定兜底策略，长宽比分布决定是纵向滑窗还是二维网格优先。若 A榜某类最大值显著高于训练集，应优先为该类保守降低并发、增加超时和重试预算。

本次统计中，A榜 long 与训练集 long 分布非常接近：像素中位数约 117M/121M，P90 约 144M/146M，说明训练集可以作为长条切块窗口和 overlap 的主要调参依据。A榜 table 的像素中位数与训练集 table 相同，P90 略高于训练集，但训练集包含更大的表格极值，因此表格兜底策略应以训练集最大样本压力为准。

文件大小不能替代像素数作为风险判断。部分 350M 级表格图片文件只有 2-4MB，说明 JPEG 压缩率会掩盖真实解码后的像素和内存压力；调度、切块和 OOM 风险应以宽高、像素、长宽比为主。

## 5. 长条类图片分析

long 类图片的主要风险是高度远大于宽度，单图内容跨越大量页面片段。本数据中 long 类宽度基本集中在 1500px 左右，高度中位数约 78k-80k，P90 接近 96k，最大高度超过 191k。所有 long 样本都超过 16M 像素预算，按 4M 工作点估算，中位数每张约 30-31 个切片。

切块策略应保持原图宽度，沿纵向滑窗切分，并在 200-400px overlap 上做接缝去重。长宽比越高，越容易出现章节标题跨块、页眉页脚重复和段落截断。对最大长宽比超过 120 的样本，质量门禁应重点检查首尾接缝、目录重复和标题层级连续性。

## 6. 表格类图片分析

table 类图片的主要风险是单页像素高、二维信息密集。table 类长宽比稳定在约 1.41-1.42，说明大多数是横纵接近固定比例的大幅表格页，而不是长条文档。A榜 table 有 24/50 张超过 16M，训练集 table 有 46/100 张超过 16M；两组都有少量超过 200M 的极端大表格。

对低于整页阈值的样本可以尝试整页作为全局参考；对高像素样本应优先二维网格切块。横向 overlap 应保护跨列表头，纵向 overlap 应保护跨行单元格，后处理需重点检查重复表头、空单元格和 HTML 标签闭合。由于 table 的文件大小中位数只有约 1.1-1.2MB，但像素最大可达 386M，不能用文件大小决定是否整页上传。

## 7. FinixDoc-VL 输入约束与切片压力

- `>16M` 图片数：220
- `>50M` 图片数：153
- `>100M` 图片数：97
- `>200M` 图片数：15
- 4M 目标切片估算总数：5,970
- 16M 硬预算切片估算总数：1,488

这些数字是理论下限，真实请求数会因为 overlap、空白切线、失败重试、表格补切而更高。因此 API 调度应按请求量峰值而不是图片张数估算耗时。

## 9. 对方案优化的建议

1. `ImageProfiler` 应保留像素、长宽比、文件大小、估算切片数，并把 `>16M` 和 `>100M` 作为风险标签写入 profile。
2. long 类默认使用纵向滑窗，优先把窗口控制在 1M-4M 像素工作点；极端长图按高度自适应增加切片数，不应为了减少请求而把切片推到 16M 附近。
3. table 类需要先按像素判断是否整页解析；超过整页阈值时采用二维切块，并保留 row/col/bbox 以支持后续阅读顺序和表格合并。
4. API 并发不宜只按图片数估算。应按 `estimated_min_chunks_4m` 加上 overlap 和重试倍率估算请求总量，再决定并发、超时和 userId 轮询。
5. 质量门禁应优先覆盖空输出、异常短输出、重复率、HTML 表格不闭合和切块覆盖缺口，这些问题与本数据集的高像素和高长宽比分布直接相关。
