## 二、当前切分方法的问题清单

### 1. 切片预算只用到 25–50%，API 调用被放大约 2 倍
[default.yaml L7-13](file:///Users/lzc/TNTprojectZ/AprojectZ/AFAC2026-Task2/configs/default.yaml#L7-L13) `max_chunk_pixels=4M`、`table_full_page_max_pixels=8M`，远低于官方 16.78M 上限。
- 50 张表格图中 **26 张恰好 15.47M**，被 8M 阈值强制切分（实际只需 1 次直传）。
- 长条图 1500×4000 = 6M/切片，相当于把 14M 预算的窗口切成 2.3 倍。
- 估算总 API：6M 预算 ≈ **1295 次**；14M 预算 ≈ **596 次**（−54%）。

### 2. LongStripChunker 对宽度零控制（[chunkers.py L51-89](file:///Users/lzc/TNTprojectZ/AprojectZ/AFAC2026-Task2/finix_restore/chunkers.py#L51-L89)）
- bbox 永远用整宽 `(0, y0, width, y1)`，window_height 是常量 4000；在长条图 1500 宽下安全，但对训练集/B 榜如果出现 width 偏大的样本（>4000）会**直接超 16.78M**。
- 缺少"宽度→window_height"的反推：`window_h = floor(budget / width)`，配置项 `long_window_height` 应该是上限而非常量。

### 3. TableGridChunker 的网格预算未含 overlap（[chunkers.py L114-132](file:///Users/lzc/TNTprojectZ/AprojectZ/AFAC2026-Task2/finix_restore/chunkers.py#L114-L132)）
- 用 `pixels/max_chunk_pixels` 估 cols/rows，再额外加 160/220 px overlap，**单切片实际像素超出预算 5–15%**。
- 全页阈值 8M 与切片上限 4M 不一致，4–8M 区间断层；A 榜 26 张 15.47M 表格本应直传但被切成 ~2 块。
- 无事后校验：`350.64M (22277×15740)` 类极端样本切完单块仍可能 >16.78M。

### 4. profiler 阈值脱离实际数据（[profiler.py L23-37](file:///Users/lzc/TNTprojectZ/AprojectZ/AFAC2026-Task2/finix_restore/profiler.py#L23-L37)）
- `aspect ≥ 10` 才走 long_strip：训练集若出现 aspect 6–10 的中等长图会被错路由到 PageChunker 等距网格切，破坏阅读流。
- `pixels ≥ 50_000_000 → extreme` 仅用于风险标签，未参与切分策略；A 榜 41% 样本 >5×预算（83.89M），但 `huge_page` 分类不存在，导致它们与 30M 样本走同一套网格逻辑。

### 5. LayoutSentry 的版式提示在切分中几乎没用上
[layout_sentry.py](file:///Users/lzc/TNTprojectZ/AprojectZ/AFAC2026-Task2/finix_restore/layout_sentry.py) 已计算 `crop_box / horizontal_blank_bands / vertical_blank_bands / column_count`，但：
- LongStripChunker 只用 `horizontal_blank_bands` 微调收尾（[chunkers.py L67](file:///Users/lzc/TNTprojectZ/AprojectZ/AFAC2026-Task2/finix_restore/chunkers.py#L67)），没用 `crop_box` 去白边（白边裁剪能直接节省 5–15% 像素，对长条图等于省 1 块切片）。
- TableGridChunker **完全没用版式提示**，等距网格盲切→易将表格行/多栏正文切到中间，直接拖累 Table TEDS 与 Read Order Edit。

### 6. 切片落盘格式无差异化（[chunkers.py L48](file:///Users/lzc/TNTprojectZ/AprojectZ/AFAC2026-Task2/finix_restore/chunkers.py#L48)）
统一 `convert("RGB")` + JPEG q=95：
- 黑白条款图被 3 倍带宽上传；q=95 在表格细线处可能产生轻微伪影。
- 没有最小像素兜底（< 4096 px²，FinixDoc-VL 下限）。

### 7. 配置与实现脱节
[`long_strip.yaml`](file:///Users/lzc/TNTprojectZ/AprojectZ/AFAC2026-Task2/configs/long_strip.yaml) 写了 `max_chunk_pixels: 12000000` 但 LongStripChunker 不消费这个字段（只接受 window_height/overlap）。

## 三、改进优化方案（按 A 榜数据画像精确化）

### 总体思路
> **预算对齐 + 形态分流 + 版式吸附 + 事后校验**：把每张图都"先尽量整页直传，超限再按形态切分，切分边界吸附空白带，最后兜底校验 ≤16.78M、≥4096"。

### 方案 A — 把切片预算对齐 FinixDoc-VL 16.78M（必做，收益最大）

引入统一常量与安全余量：

```python
# finix_restore/chunkers.py 顶部
FINIX_MAX_PIXELS = 16_777_216
FINIX_MIN_PIXELS = 4_096
SAFETY_MARGIN    = 0.85          # 留 15% 给 overlap 与误差
FULL_PAGE_BUDGET = int(FINIX_MAX_PIXELS * SAFETY_MARGIN)  # ≈14.26M
CHUNK_BUDGET     = 12_000_000    # 单切片目标，预留与 max 之间的安全区
```

`default.yaml` 同步：

```yaml
chunk:
  full_page_max_pixels: 14000000   # 单图直传上限
  max_chunk_pixels: 12000000       # 切片像素目标
  long_window_height_max: 9000     # 1500x9000 ≈13.5M，给 overlap 留余量
  long_min_tail_height: 2000       # 不足并入上块
  long_vertical_overlap: 320
  table_horizontal_overlap: 200
  table_vertical_overlap: 240
  table_resize_long_side_max: 5000 # 大表预缩放上限（仅 table_page）
```

**预期影响**：A 榜 26 张 15.47M 表格 → 全部 1 次直传；50 张长条图按 1500 宽 +  9000 高约 ~415 次（vs 当前 939 次）。

### 方案 B — LongStripChunker 增加"宽度感知 + 自适应窗口"

关键片段（替换 [chunkers.py L57-89](file:///Users/lzc/TNTprojectZ/AprojectZ/AFAC2026-Task2/finix_restore/chunkers.py#L57-L89) 的核心）：

```python

    chunks[-1] = _extend_bottom(chunks[-1], height)
    break

# 4) 切片像素超 FINIX_MAX_PIXELS 时事后等比缩放（兜底）
```

**收益**：long_strip 单图切片数 -30%–50%，且消除"训练集若出现宽 >4096"的超限风险。

### 方案 C — TableGridChunker 增加"预缩放 + 含 overlap 预算 + 边界吸附"

关键片段（替换 [chunkers.py L114-132](file:///Users/lzc/TNTprojectZ/AprojectZ/AFAC2026-Task2/finix_restore/chunkers.py#L114-L132)）：

```python
# 1) 大表预缩放：长边 > resize_long_side_max 或像素 > FULL_PAGE_BUDGET 时
#    等比缩到 ~ FULL_PAGE_BUDGET（高密度表格仍保留 ≥150 DPI 等效）
if profile.pixels > FULL_PAGE_BUDGET and profile.long_side > self.resize_long_side_max:
    image = _resize_to_budget(profile.path, FULL_PAGE_BUDGET)

# 2) 缩放后整页 ≤ full_page_max_pixels → 1 次直传
if effective_pixels <= self.full_page_max_pixels:
    return [_full_page_chunk(profile)]

# 3) 网格预算含 overlap：
def _grid_with_overlap(W, H, h_ov, v_ov, budget):
    cols = rows = 1
    while True:
        cw = W / cols + (2 * h_ov if cols > 1 else 0)
        ch = H / rows + (2 * v_ov if rows > 1 else 0)
        if cw * ch <= budget:
            return cols, rows
        if cw >= ch: cols += 1
        else:        rows += 1

# 4) 网格边界吸附 LayoutHints.vertical/horizontal_blank_bands
def _snap_to_blank(boundary, bands, tol):
    cand = [b for b in bands if abs((b[0]+b[1])//2 - boundary) <= tol]
    return min(cand, key=lambda b: abs((b[0]+b[1])//2 - boundary)) if cand else None
```

**收益**：
- A 榜 26 张 15.47M 表格 0 切分；24 张大表平均切片数从 4–6 降到 2–3。
- 350.64M 极端样本：先缩放到 ~14M 单次直传，必要时再 2×2 网格，**最多 4 次而非当前 88 次**。
- 边界吸附避免切到表格行中部，TEDS 显著改善。

### 方案 E — 事后兜底（必加，消除"超限/过小"风险）

在 [chunkers.py `_save_crop`](file:///Users/lzc/TNTprojectZ/AprojectZ/AFAC2026-Task2/finix_restore/chunkers.py#L44-L48) 加入两道护栏：

```python
def _save_crop(source, bbox, out_path,
               max_pixels=FINIX_MAX_PIXELS,
               min_pixels=FINIX_MIN_PIXELS):
    crop = Image.open(source).crop(bbox)
    if crop.width * crop.height > max_pixels:
        s = (max_pixels / (crop.width * crop.height)) ** 0.5
        crop = crop.resize((int(crop.width*s), int(crop.height*s)), Image.LANCZOS)
    if crop.width * crop.height < min_pixels:
        s = (min_pixels * 4 / (crop.width * crop.height)) ** 0.5
        crop = crop.resize((int(crop.width*s), int(crop.height*s)), Image.LANCZOS)
    # 长条文字优先灰度上传（节省带宽），表格/含图保留 RGB
    mode = "L" if _looks_text_only(crop) else "RGB"
    crop.convert(mode).save(out_path, "JPEG", quality=92, subsampling=2, optimize=True)
```

**收益**：无论上游切多大都不会触发服务端下采样/超时；同时把 long_strip 上传体积压一半。

- 三个配置 (`default / long_strip / table_grid`) 共享 `full_page_max_pixels / max_chunk_pixels / overlap` 同一组键，避免脱节。

## 一句话总结

A 榜本质 = **50 张 1500×~78k 的"超长面条图" + 50 张 √2 比例的"大表格"**。当前默认 `max_chunk_pixels=4M / full_page=8M` 只用了 FinixDoc-VL 25–50% 的预算，**API 被放大近 2 倍**。优先做 **预算对齐到 14M + 事后兜底（≤16.78M & ≥4096）**，再加上 **长条宽度感知** 与 **表格预缩放 + 边界吸附**，就能在不动现有 dedup/normalizer 的前提下把 100 张总调用从 ~1300 压到 ~550，同时 Text Edit / Table TEDS / Read Order Edit 三项都受益。
