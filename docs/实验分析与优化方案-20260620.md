# 训练集小样本实测分析与下阶段优化方案（2026-06-20）

> 本文记录一次基于真实 FinixDoc-VL 调用的训练集分层小样本实验、官方三维指标评分、根因定位与下阶段优化方案。所有数据均来自真实 API 产物，未构造、未硬编码测试集结果。原始证据见 `outputs/exp_train_sample/findings.json`。

## 1. 实验设计

### 1.1 目标

1. 在训练集上用官方三维指标（Text Edit / Table TEDS / Read Order Edit）量化当前 pipeline 真实表现。
2. 定位失分根因，区分「切分」「归一化/结构」「表格」三类问题。
3. 验证「最佳图片切分方案」相关假设，给出可执行的下阶段优化方案。

### 1.2 样本抽取（确定性、可复现、无文件名特判）

脚本 `outputs/_exp_sample.py`：对 long、table 两个训练子集各按「像素分位」均匀取 10 张，覆盖小/中/大极端规模。抽样只依赖图片像素，不依赖任何文件名特征，符合 `AGENTS.md` 禁止面向测试集硬编码的红线。

| 子集 | 张数 | 像素范围 |
| --- | --- | --- |
| long | 10 | 46.8M ~ 222.8M |
| table | 10 | 15.5M ~ 350.6M |

### 1.3 运行与评分链路

- 运行：`python -m finix_restore.cli --config outputs/exp_train_sample/exp_conservative.yaml`（保守并发配置）。
- 评分：`python -m finix_restore.eval.cli --pred <submission.csv> --gt "data/AFAC 训练数据集/.../mds"`，目录模式按 uuid 直接匹配 GT。
- 评分口径与赛题一致：`Overall = ((1-TextEdit)*100 + TableTEDS + (1-ReadOrderEdit)*100) / 3`。

## 2. 关键发现

### 2.1 工程阻塞：FinixDoc-VL 连接级限流（最高优先级）

首轮以 `image_concurrency=2 / api.concurrency=4` 运行时，几乎所有切片返回 `retryable_error`，merged 全空。直接探测定位到根因：

- 小图（7KB）1 秒正常返回；真实切片单独调用也能成功（long 切片 10-45s，table 切片 84s+）。
- 但**连续/并发请求会触发连接级限流**：`RemoteDisconnected`（服务端主动断开）、`SSLError: Max retries exceeded`（连接被拒，秒级失败）、以及 240s 超时。
- 对照实验（`outputs/_api_serial.py`）：并发打 6 个切片成功 3/6；改为「串行 + 请求间隔 2s + 失败换 userId + 长退避重试」后成功 6/6。

**已实施修复**（小而集中）：
- `finix_restore/finix_api.py`：重试退避由 `2^i`（1/2/4s）改为 `5*2^i + 抖动`（上限 40s），覆盖连接错误。修复后 long 连续运行成功率显著提升（110+ 切片仅 10-14 次失败）。
- 同步更新 `tests/test_finix_api.py` 退避断言。

### 2.2 数据正确性 Bug：空 merged 被 resume 当作有效缓存

table 首图 `00332e7f` 的 merged 文件为 0 字节（来自首轮全失败），但 resume 逻辑把它当作有效缓存复用，导致该图**永久跳过、无法自愈**（qc 显示 `from_merged_cache:1, chars:0`）。

**已实施修复**：`finix_restore/pipeline.py::_read_merged` 对空白 merged 返回 `None`，强制重跑。全部 136 个单测通过。

### 2.3 Long 类评分（4 个已完成样本，真实分数）

| 指标 | 值 | 解读 |
| --- | --- | --- |
| Text Edit | 0.0817 | 文本识别准确，非主要失分项 |
| Read Order Edit | 0.6167 | **主要失分项** |
| Table TEDS | 23.62 | 4 张中 2 张含表格，表格仍是短板 |
| Overall | 63.99 | — |

**Read Order 失配分类（1369 个逻辑块，`outputs/_mismatch_cat.py`）**：

| 类型 | 占比 | 性质 |
| --- | --- | --- |
| 完全一致 | 44.3% | — |
| 内容/分段差异（content_or_split_diff） | 31.9% | VLM 与 GT 的分段/断句不一致，或个别字差异 |
| 段落标点差异（none<-none） | 8.4% | 段落级标点/空白差异 |
| 标题层级差异合计 | ~23% | VLM 标题层级判断与 GT 不符 |

标题层级差异明细：`#<-##`(5.7%)、`###<-##`(5.1%)、`###<-*`(1.6%，子标题被渲染成列表项) 等。

**关键证伪**：what-if 实验（`outputs/_whatif_style.py`）只对齐「编号后空格」风格，Read Order 仅从 0.617 微降到 0.611。说明**空格不是主因**，真正驱动是「标题层级（~23%）+ 段落切分/断句（~40%）」。

### 2.4 Table 类（密集费率表）系统性崩溃

- 真实 TEDS 样本：整页 14M 直传 `00332e7f` TEDS=13.79、Text Edit=0.894；网格切分 `00332e7f` TEDS=9.27、Text Edit=0.557。
- 表现：密集数字费率表，整页直传 OCR 数字大量错误（如 `85724` 识别成 `8572`、整块数字重复）；网格切分后单切片 84s+，极易超时；TEDS 普遍个位数到 20。
- 47M 表格 = 3×3=9 个切片，单独跑也大面积超时，table 链路**当前不可用**。

## 3. 根因小结

| 维度 | 根因 | 影响指标 |
| --- | --- | --- |
| 工程/调度 | API 连接级限流，原退避过短、并发过高 | 全链路（失败=空输出=三项全崩） |
| 工程/缓存 | 空 merged 被 resume 复用 | 鲁棒性、可复现 |
| 结构/归一化 | VLM 标题层级与 GT 不一致（~23% 块） | Read Order |
| 阅读流/分段 | VLM 分段/断句与 GT 不一致（~40% 块） | Read Order |
| 表格切分 | 密集数字表整页 OCR 错、网格切片过大超时 | Table TEDS、Text Edit |

## 4. 下阶段优化方案（按优先级）

### P0-1 API 调度稳定化（已起步，需补全）
- 已做：长退避 + 抖动覆盖连接错误。
- 待做：
  - 全局有效并发降到「连接限流安全区」（建议总连接 ≤ 2），并在 `_post_chunk` 失败时**优先换 userId 而非阻塞等待同一 userId**（当前 `concurrency.py` 先占 per-user 信号量会串行化到单 user）。
  - 请求间引入最小间隔/令牌桶，避免突发触发限流。
  - 验收：long 单图失败切片比例 < 5%，table 单图可完整产出非空 merged。

### P0-2 表格切分与超时治理（决定 TEDS 能否拿分）
- 缩小 table 切片目标像素（如 target 3-4M）以把单切片耗时压到超时阈值内；或对密集数字表降低单切片高度，按表格横线切。
- 提高 table `timeout_seconds`，并对 table 切片单独限流（并发=1）。
- 验收：table 小/中样本 TEDS 较当前（9-23）明显提升，且无整图超时。

### P1-1 标题层级归一化（直接提升 Read Order ~23% 块）
- Prompt 侧：明确要求按条款编号深度输出标题层级（`1.`→`#`/`##`，`1.1`→`###`，不要把子标题输出成列表 `*`）。
- 后处理侧：在 `normalizer` 增加「编号深度 → 标题层级」的稳健映射（已有 `_heading_level_for` 雏形，可扩展覆盖 `*`/`-` 子标题误判）。
- 验收：`marker_diff[###<-*]`、`#<-##`、`###<-##` 三类合计占比下降。

### P1-2 分段/断句对齐（Read Order 最大块，~40%）
- 这是 Read Order 第一大失分源，但耦合 VLM 行为，收益与风险并存。
- 建议：先用 Prompt 约束「保持原文自然段，不要拆分/合并段落」；再审视 `dedup` 接缝合并是否在边界处引入额外断行。
- 验收：`content_or_split_diff` 占比下降，且 Text Edit 不退化。

### P2 实验矩阵补全
- 完成 long10 + table10 全量评分，填入 `docs/experiments.md` 记录表。
- 增加切分消融：long `target_pixels` 6M vs 4M、table 网格 vs 整页、空白带切线开关，对比三维指标。

## 5. 复现入口

```bash
# 1) 固定分层样本
python outputs/_exp_sample.py
# 2) 跑预测(保守配置)
python -m finix_restore.cli --input_dir "outputs/exp_train_sample/long/images" \
  --output_csv outputs/exp_train_sample/long/submission.csv \
  --work_dir outputs/exp_train_sample/long/run \
  --config outputs/exp_train_sample/exp_conservative.yaml --image_concurrency 1
# 3) 构造CSV并评分
python outputs/_build_csv.py outputs/exp_train_sample/long/run/merged outputs/exp_train_sample/long/images outputs/exp_train_sample/long/partial.csv
python -m finix_restore.eval.cli --pred outputs/exp_train_sample/long/partial.csv \
  --gt "data/AFAC 训练数据集/finixdocbench_huge_long_100/mds" \
  --output outputs/exp_train_sample/long/partial_metrics.json
```
