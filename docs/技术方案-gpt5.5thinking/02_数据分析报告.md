## 5. 数据难点归纳

### 5.1 长条条款类

| 难点 | 数据证据 | 技术影响 |
| --- | --- | --- |
| 高度极端 | 训练最高 191,578px，测试采样最高 113,690px | 必须纵向滑窗，不能全图解析。 |
| 标题多级且密集 | 长条 GT 平均 86.9 个标题行，最多 240 个 | 需要标题编号和 Markdown 层级修复。 |
| 目录与正文重复 | 样本常以“条款目录”开头 | 去重必须区分目录重复和接缝重复。 |
| 段落跨切块 | 平均 573.7 行，最多 1409 行 | 需要段落续接与边界重跑。 |
| 局部 HTML 表格 | 长条 GT 也可能含 HTML 表格 | 通用文本拼接必须兼容表格块。 |

### 5.2 超大表格类

| 难点 | 数据证据 | 技术影响 |
| --- | --- | --- |
| 单元格数量巨大 | 表格 GT 平均 14,025 个 `<td>`，最多 46,438 个 | 普通 VLM 输出容易漏行、错列、截断。 |
| 空单元格密集 | 空 `<td>` 总数 38,088 | 必须保持空位，不能自动压缩空列/空格。 |
| 数字文本占主导 | 中文字符均值仅 148.3 | 数字、百分号、逗号、小数点错误影响字级分数。 |
| 表格行列连续 | rowspan/colspan 在采样表格类中未出现，但行列数量巨大 | 可采用规则化矩阵校验：每行列数一致性、空单元格补齐。 |
| 图像像素极大 | 训练表格最大 386.57M 像素，A 榜采样最大 350.64M 像素 | 需要网格切块、局部重叠和表格拼接。 |

## 6. 对技术方案的启示

1. 先分类再切块：长条条款采用纵向滑窗；表格页面采用二维网格或基于行列投影的切块。
2. 采样 GT 表明表格应优先输出 HTML `<table>`，而不是强行转成管道式 Markdown 表格。
3. 去重策略必须基于位置和语义类型。目录区、页眉页脚、切块重叠区、正文重复引用需要区别处理。
4. 表格拼接应保留所有空单元格，并在最终阶段做 HTML 标签闭合、行列数量一致性和异常短行检测。
5. 对长条文本，不应过度规范化标点、编号和金额，因为编辑距离指标会惩罚错误替换。
6. A 榜模拟提交文件只能验证 CSV 格式，不能用于评分或训练。

## 7. 建议的验证集划分

采样训练集只有 20 条，建议不要追求复杂训练，而采用人工分层验证：

| 验证组 | 样本 | 验证重点 |
| --- | --- | --- |
| Long-Easy | 较短长条图 | 基础标题、段落、目录恢复。 |
| Long-Hard | 高度 > 90,000px 的长条图 | 滑窗、接缝去重、章节连续性。 |
| Table-Small | 像素 < 5,000 万的表格图 | HTML 表格输出与行列校验。 |
| Table-Large | 像素 > 1 亿的表格图 | 网格切块、表格跨块拼接、超时控制。 |
