# 复杂金融文档还原挑战：实施清单与风险控制

## 1. 开发任务清单

| 优先级 | 任务 | 产出 | 验收方式 |
| --- | --- | --- | --- |
| P0 | 建立工程骨架 | `main.py`、`run.sh`、`requirements.txt`、配置目录 | 空目录运行可输出空提交或清晰报错。 |
| P0 | 图片画像统计 | `profiles/*.json` | 与 PIL 读取尺寸一致。 |
| P0 | API 适配与缓存 | `api_raw/*.md` | 同一切块二次运行不重复请求。 |
| P0 | 长条滑窗切块 | `chunks/*/manifest.json` | 切块覆盖全图，无间隙。 |
| P0 | CSV 输出 | `submission.csv` | pandas 可读，列名与行数正确。 |
| P1 | 接缝去重 | `merged/*.md` | 人工抽查无明显重复段。 |
| P1 | 表格 HTML 修复 | 表格合法化函数 | 单元测试覆盖标签闭合、空 td 保留。 |
| P1 | 表格网格切块 | 表格类 manifest | 大图切块像素低于阈值。 |
| P1 | 阅读顺序规则 | 排序器 | 多栏/目录/表格块顺序人工抽查。 |
| P2 | 质量门禁重跑 | `qc/*.json` | 异常短、空输出、HTML破损可触发。 |
| P2 | 运行压测 | `logs/profile.jsonl` | 估算 100 张测试图总耗时。 |
| P2 | 复现文档 | `docs/reproduce.md` | 新环境按步骤可复现提交文件。 |

## 4. 单元测试建议

1. `test_manifest_coverage`：验证切块 bbox 覆盖全图，无负坐标、无明显间隙。
2. `test_submission_schema`：验证输出 CSV 只有两列，且行数和输入图片数一致。
3. `test_dedup_overlap`：构造前后切块重复文本，验证只保留一次。
4. `test_html_table_close`：构造缺失 `</table>`、`</tr>` 的 HTML，验证可修复。
5. `test_keep_empty_td`：验证空 `<td></td>` 不被删除。
6. `test_no_secret_in_repo`：扫描代码、文档和日志，确保不含真实 API Key。

## 5. 运行命令建议

```bash
# 安装依赖
pip install -r requirements.txt

# 设置环境变量，不要把真实值提交到仓库
export FINIX_USER_ID="your_user_id"
export FINIX_API_KEY="your_api_key"
export FINIX_API_URL="https://finixdocapi.alipay.com/api/finix_doc/call_with_file"

# 运行 A/B 榜预测
python main.py   --input_dir /path/to/test/images   --output_csv outputs/submission.csv   --config configs/default.yaml   --cache_dir outputs/cache
```

## 6. 质量门禁阈值建议

| 门禁 | 初始阈值 | 说明 |
| --- | --- | --- |
| 单切块最大像素 | 8M–16M | 根据 API 稳定性调整。 |
| 空响应重试次数 | 3 | 超过后记录失败并进入降级策略。 |
| 文本重复检测窗口 | 800 字 | 长条文档可增大，表格可降低。 |
| 重复相似度阈值 | 0.85–0.92 | 结合人工抽查调参。 |
| 异常短输出阈值 | 同类长度 P10 以下 | 按长条/表格分别统计。 |
| HTML 标签修复失败 | 阻断或重跑 | 表格 TEDS 对结构非常敏感。 |

## 8. 最小可行版本（MVP）定义

MVP（Minimum Viable Product，最小可行产品）应至少具备：

1. 图片自动分类为长条/表格/普通页。
2. 长条图片纵向滑窗切块。
3. 表格图片按最大像素阈值二维切块。
4. FinixDoc-VL API 调用、缓存、重试。
5. 按坐标拼接 Markdown。
6. 基础接缝去重。
7. HTML 表格标签闭合修复。
8. 输出合法 `submission.csv`。

在 MVP 基础上，优先迭代表格行级合并、目录保护、标题层级修复和质量门禁重跑。
