# 复杂金融文档还原挑战：Markdown 文档交付说明

生成日期：2026-06-17

本目录包含针对“复杂金融文档还原挑战”的需求、数据、技术调研与技术架构文档。文档基于用户提供的赛题说明、FinixDoc-VL API 说明与 `data-0.1.zip` 10% 采样数据，并结合联网检索的公开技术资料整理。

## 核心结论

1. 本赛题不是单纯 OCR（Optical Character Recognition，光学字符识别）任务，而是超大金融图片到高保真 Markdown 的结构化还原任务。评分同时约束文本编辑距离、表格 TEDS（Tree Edit Distance based Similarity，基于树编辑距离的相似度）与阅读顺序编辑距离。
2. 数据呈现明显双峰：长条保险条款图像宽度约 1500px、高度可达 191,578px；超大表格图像接近 A 系列纸张比例，但最大像素超过 3.8 亿。直接全图送入视觉语言模型会触发内存、上下文与超时风险。
3. GT（Ground Truth，标准答案）中，长条文档以多级标题、目录、段落、列表为主；表格文档以 HTML `<table>` 为主，而不是管道式 Markdown 表格。因此技术方案需要支持 HTML 表格拼接、空单元格保持与行列对齐。
4. 推荐方案是“轻量本地感知 + 自适应切块 + FinixDoc-VL API 解析 + 坐标驱动重组 + 多轮后处理质检”的工作流。最终提交工程应严格遵循赛题模型限制，仅使用 FinixDoc-VL 作为唯一大模型/视觉语言模型（Vision-Language Model, VLM）接口，辅助组件只使用 CPU 可运行的规则或小于 10M 参数的轻量模型。

## 安全与合规说明
