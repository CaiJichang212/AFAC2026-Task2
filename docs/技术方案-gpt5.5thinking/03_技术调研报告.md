# 复杂金融文档还原挑战：技术调研报告

## 1. 调研目标

本调研围绕赛题所需的“复杂金融文档图片到高保真 Markdown”能力展开，重点覆盖 OCR（Optical Character Recognition，光学字符识别）、文档版面分析（Document Layout Analysis）、阅读顺序恢复（Reading Order Recovery）、表格结构识别（Table Structure Recognition）、Markdown/HTML 结构化输出、后处理纠错与评测指标。

需要特别说明：本报告调研的开源项目和论文主要用于理解方法、设计规则、构造离线辅助工具和制定验证策略。最终提交工程必须遵循赛题规则，仅使用 FinixDoc-VL 作为唯一大模型/视觉语言模型接口；其他大模型或超参数本地模型不能进入最终推理链路。

## 2. 相关知识体系

### 2.1 OCR 与文档理解的差异

OCR 关注图像中文字识别，输出通常是字符、文本行或文本框；文档理解还需要推断标题层级、段落归属、表格行列、阅读顺序和结构化标记。对本赛题而言，单独提升 OCR 字符准确率不足以获得高分，因为评分同时包含表格 TEDS 与阅读顺序编辑距离。

### 2.2 版面分析

版面分析需要识别页面中的标题、正文、列表、表格、图片、脚注、页眉页脚等区域。传统方法可使用投影、连通域、边缘检测和规则；深度学习方法通常使用目标检测或分割模型。本赛题最终方案不能依赖大模型，但可以使用轻量规则检测空白区、表格线和列结构，用于切块和排序。

### 2.3 阅读顺序恢复

阅读顺序恢复是将页面块排序为人类阅读流。常见挑战包括多栏、浮动表格、跨页标题、目录和脚注。对长条图像，简单纵向排序通常可用；对多栏或表格页面，需要加入列检测、块类型、编号序列和表格坐标。

### 2.4 表格结构识别与 TEDS

表格结构识别不仅要识别单元格文字，还要恢复行、列、空单元格、合并单元格和表头层级。TEDS（Tree Edit Distance based Similarity，基于树编辑距离的相似度）将表格转换为树结构并计算相似度，因此 HTML 标签结构和单元格拓扑非常关键。

### 2.5 Markdown 与 HTML 表格

Markdown 支持标题、段落、列表、代码块和管道表格，但管道表格很难表达复杂行列合并。本赛题 GT 中表格大量采用 HTML `<table>`，因此系统应允许 Markdown 文档中嵌入 HTML 表格，并对 HTML 结构做合法性校验。

## 4. 技术路线比较

### 4.1 全图直接解析

优点是流程简单，避免切块拼接；缺点是超大图像容易超时、OOM、文字细节丢失。结合采样数据中最大数亿像素的图片，此路线不可作为主方案，只适合小图兜底。

### 4.2 固定滑窗切块

优点是实现简单，适合长条文档；缺点是固定窗口可能切断表格行、标题和段落，导致重复或截断。需要加入 overlap、空白线寻找和后处理去重。

### 4.3 自适应结构切块

优点是能根据图像类型选择纵向滑窗、表格网格或列切分，并尽量避开文字与表格线；缺点是工程实现复杂。该路线最符合本赛题特点，建议作为主方案。

### 4.4 OCR 坐标优先方案

使用轻量 OCR 或图像投影先得到文本/线条坐标，再按坐标切块和排序。优点是可解释、对拼接友好；缺点是 OCR 坐标本身可能不准，且中文金融文档字符识别未必稳定。建议作为辅助，不把 OCR 文本直接作为最终输出。

### 4.5 VLM 输出优先方案

主要依赖 FinixDoc-VL 的 Markdown 解析能力，系统负责切块、调度和重组。优点是遵守赛题模型限制，能利用官方模型对金融文档的优化；缺点是需要解决跨块一致性和 API 稳定性。建议作为最终主线。

## 5. 关键算法调研与可落地实现

### 5.1 图像预处理

可采用 PIL/OpenCV 读取图像尺寸、灰度化、小图缩略图、二值化、水平/垂直投影、边缘检测。目标不是识别全部文字，而是寻找空白切线、表格线密度和列分隔位置。

### 5.2 长条文档切块

长条文档适合纵向窗口：窗口高度 2,000–6,000px，重叠 150–400px。实际参数需要结合 API 超时、文本密度和返回长度调优。切线应优先落在低墨迹密度区域，避免切断标题或段落。

### 5.3 表格文档切块

表格文档应优先检测表格线和行列投影，在网格边界处切分。推荐保留双向 overlap：横向用于跨列文本，纵向用于跨行文本；最终用行级 key 或坐标顺序拼接 HTML `<tr>`。

### 5.4 去重与续接

可组合以下策略：

1. 前后切块文本的最长公共子串/公共后缀前缀匹配。
2. 字符 n-gram Jaccard 相似度。
3. 标题编号连续性判断，例如 `2.1.1` 后应优先接 `2.1.2` 或正文续段。
4. 目录区保护：目录项中的标题重复不应被误删。
5. HTML 表格保护：`<tr>` 粒度去重，而不是在单元格内部做激进文本删除。

### 5.5 表格合法化

对 HTML 表格执行：

1. 标签栈检查：`table`、`tr`、`td`、`th` 是否闭合。
2. 行列数统计：检测异常短行、异常长行。
3. 空单元格保护：保持 `<td></td>`，不自动删除。
4. 数字规范：避免把 `0.00` 改成 `0`，避免中文逗号和英文逗号误替换。
5. 跨块表格合并：如果相邻切块分别以 `<table>` 结尾/开头，可按 `<tr>` 合并为单表。

## 6. 评测指标对方案设计的影响

| 指标 | 常见失分 | 工程对策 |
| --- | --- | --- |
| Text Edit | 漏字、错字、重复、幻觉、数字标点错误 | 边界重叠、保守规范化、API 缓存重试、重复检测。 |
| Table TEDS | 行列错位、HTML 标签错、空单元格缺失、跨块表格断裂 | HTML 表格合法化、行列一致性校验、表格块单独拼接。 |
| Read Order Edit | 多栏顺序错、目录/正文错位、表格插入位置错 | 坐标排序、列检测、标题编号和块类型联合排序。 |

## 7. 推荐技术栈

| 层级 | 推荐组件 | 说明 |
| --- | --- | --- |
| 基础语言 | Python 3.10+ | 满足赛题代码语言要求。 |
| 图像处理 | Pillow、OpenCV-python-headless、numpy | 获取尺寸、裁剪、投影、表格线/空白线检测。 |
| 文本处理 | regex、beautifulsoup4/lxml（可选） | Markdown/HTML 清洗、标签检查、表格解析。 |
| 数据处理 | pandas | 生成提交 CSV 与统计报告。 |
| 相似度 | rapidfuzz / python-Levenshtein（可选） | 接缝去重、块级相似度。 |
| HTTP | requests / httpx | API 调度、重试、超时控制。 |
| 配置 | pydantic / yaml / dotenv | 管理 API、切块、并发、路径参数。 |
| 日志 | loguru / logging | 结构化日志与复现追踪。 |

如果依赖包过多会影响封闭环境复现，最终可把核心相似度算法和 HTML 修复规则手写实现，减少外部依赖。

## 8. 调研到方案映射

1. 从 PaddleOCR、MinerU、Docling 借鉴“布局感知→结构化解析→Markdown 导出”的流水线思想。
2. 从 PubTabNet/TEDS 和 Table Transformer 借鉴 HTML 表格树结构、行列网格与结构评估优先的思想。
3. 从 ReadingBank/LayoutReader 借鉴阅读顺序是独立任务的认知，而不是 OCR 后天然排序。
4. 从 LayoutParser 借鉴模块化工程组织、布局块对象和可视化调试方法。
5. 从 Donut/Nougat 借鉴端到端图片到标记语言的输出范式，但最终不接入这些模型。
