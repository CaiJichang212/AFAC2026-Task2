# 复杂金融文档还原挑战：赛题需求文档

## 1. 背景与问题定义

金融行业文档包含保险条款、费率表、特约批注、责任说明等关键业务信息，常见形态是扫描图、截图或长图。该类文档具有高文本密度、非标准版式、多级标题、目录、跨页表格、嵌套表格、多栏排版、脚注和特殊符号等特点。传统 OCR（Optical Character Recognition，光学字符识别）通常只能给出局部文本结果，难以稳定恢复阅读流、标题层级、表格拓扑和跨切块连续性。

本赛题目标是构建一个端到端文档解析系统，将超长或超大金融文档图片自动还原为与原文严格对应的 Markdown 结构化文本。系统需要在视觉上下文受限、图片像素超大、API 可能超时、切块边界易重复或截断的条件下，尽量提升文本完整性、结构保真度与工程鲁棒性。

## 2. 任务目标

系统输入为测试集图片文件，输出为标准 CSV（Comma-Separated Values，逗号分隔值）文件。CSV 只包含 `file_name` 与 `ground_truth` 两列，其中 `ground_truth` 字段写入系统预测的 Markdown 字符串。

核心目标可拆解为四类：

| 目标 | 含义 | 对系统的要求 |
| --- | --- | --- |
| 内容完备性（Completeness） | 覆盖原图中所有有效文字、表格、脚注、符号 | 避免漏检、截断、幻觉、重复；切块必须覆盖全图有效区域。 |
| 结构高保真（Structural Fidelity） | 保持标题、段落、列表、表格结构 | 正确输出 `#` 至 `######` 标题层级、段落边界、列表层级、HTML/Markdown 表格。 |
| 阅读流顺序（Reading Order） | 与人类真实阅读顺序一致 | 正确处理多栏、目录、跨块表格、跨页章节、页眉页脚。 |
| 工程鲁棒性（Robustness） | 面向超大图、密集表格、错行目录稳定运行 | 控制 OOM（Out of Memory，内存溢出）、API 超时、重试、缓存、断点续跑与输出校验。 |

## 3. 范围定义

### 3.1 范围内

1. 读取训练集、A/B 榜测试集图片与目录。
2. 对超大图片做轻量预处理、感知和自适应切块。
3. 调用 FinixDoc-VL API 对切块图片进行文档解析。
4. 将切块 Markdown 按坐标、阅读流与文本相似度进行重组。
5. 对文本重复、截断、标题层级、表格边界、HTML 标签合法性进行后处理。
6. 生成符合赛题要求的 `submission.csv`。
7. 生成可复现日志、缓存与调试中间产物，支持封闭环境复现。

### 3.2 范围外

1. 最终提交工程不接入除 FinixDoc-VL 之外的商业或开源大模型 API。
2. 不使用 GPU 依赖的大模型或参数量超过 10M 的本地模型作为最终推理组件。
3. 不针对 B 榜样本进行硬编码输出或文件名级规则投机。
4. 不改写 Ground Truth 标准，不提交非 UTF-8 编码文件。

## 4. 输入与输出需求

### 4.1 输入

| 输入项 | 格式 | 说明 |
| --- | --- | --- |
| 原始图片 | `.jpg` / `.png` 等图片 | 赛题 API 仅支持图片输入；采样数据主要为 `.jpg`。 |
| 可选训练标签 | `.md` | 训练集提供与图片对应的 Markdown GT，用于分析和参数调优。 |
| 映射文件 | `.csv` | 训练集 `id_mapping.csv` 可用于内部追踪。 |
| API 配置 | 环境变量 | `FINIX_USER_ID`、`FINIX_API_KEY`、API 地址、超时与重试参数。 |

### 4.2 输出

| 输出项 | 格式 | 说明 |
| --- | --- | --- |
| 预测文件 | `submission.csv` | 必须包含表头 `file_name,ground_truth`，行数与测试图片数一致。 |
| 中间缓存 | JSON/Markdown/图片切块 | 保存切块坐标、API 返回、重试记录、拼接结果，用于断点续跑和复现。 |
| 日志 | `.log` / `.jsonl` | 记录文件级耗时、切块数、API 状态、质检问题。 |

## 5. 功能需求

### 5.1 图像感知与分类

系统应先读取图片宽高、像素数、长宽比、文件大小，并将样本粗分为长条条款类、超大表格类、普通页面类、异常图片类。分类结果用于选择切块策略。

建议规则：

- 长宽比大于 10 或高度大于 30,000px：判为长条文档。
- 宽高比接近 1.414 且像素数大于 1,500 万：判为表格图或页面截图。
- 单边超过 8,000px 或总像素超过 8,000 万：启用更保守的切块与并发控制。

### 5.2 自适应切块

切块模块应满足：

1. 覆盖完整图片，不丢失边缘内容。
2. 控制每个切块像素数和边长，降低 API 超时与 OOM 风险。
3. 在切块之间保留重叠区（Overlap），用于消除接缝截断。
4. 长条文档以纵向滑窗为主；表格文档以网格切块与行/列边界对齐为主。
5. 对表格切块尽量避开行线与文字区域，必要时使用投影统计寻找空白切线。

### 5.3 API 调度

API 适配层应负责表单上传图片、记录请求参数、处理超时/失败、重试、限速与缓存。由于赛题 API 只接收图片并返回 Markdown，系统不应依赖外部 Prompt 参数；若后续接口开放 Prompt，可将解析规范作为可配置模板接入。

### 5.4 Markdown 重组

重组模块应把切块 Markdown 合并为单文档 Markdown。要求：

1. 基于切块坐标确定初始顺序。
2. 基于标题编号、目录层级、段落连续性和表格边界修正阅读流。
3. 通过最长公共后缀/前缀、编辑距离、n-gram 相似度消除重叠区重复。
4. 对被截断段落进行拼接，对被拆开的 HTML `<table>` 进行行级合并。
5. 保留空单元格、数字精度、特殊符号与中文标点。

### 5.5 质量门禁

每张图片输出前应执行自动质检：

| 检查项 | 目的 | 失败处理 |
| --- | --- | --- |
| CSV 行数与文件名 | 防止缺漏/多报 | 阻断提交。 |
| UTF-8 与换行转义 | 防止 CSV 错位 | 自动重新写入并校验可读性。 |
| HTML 表格标签闭合 | 防止 TEDS 崩坏 | 规则修复或重跑相关切块。 |
| 重复率 | 检查接缝重复 | 触发去重策略。 |
| 疑似截断率 | 检查切块边界断句 | 扩大 overlap 或重跑边界切块。 |
| 标题层级跳变 | 检查结构异常 | 用编号规则修正或标记复核。 |
| API 返回空结果 | 检查解析失败 | 自动重试或降采样后重跑。 |

## 6. 非功能需求

| 维度 | 需求 |
| --- | --- |
| 合规性 | 最终提交只使用 FinixDoc-VL API 作为唯一 VLM（Vision-Language Model，视觉语言模型）接口；本地辅助模型 CPU 可运行且参数量小于 10M。 |
| 可复现性 | 统一 Python 工程；提供 `main.py` 或 `run.sh`；固定随机种子；保存配置与缓存哈希。 |
| 稳定性 | 单文件失败不影响全局；支持断点续跑；输出结果与日志一一对应。 |
| 性能 | B 榜 100 张图片应在赛题要求的 3 小时内完成；通过并发、缓存与失败重试控制总耗时。 |
| 可维护性 | 模块化组织：感知、切块、API、重组、后处理、质检、提交生成分离。 |
| 可审计性 | 不硬编码测试结果；日志记录每个输出由哪些切块和 API 返回组成。 |

## 7. 主要难点分析

### 7.1 超大图像与视觉长上下文限制

采样集中训练长条图最大为 1500×191,578，训练表格图最大为 16,527×23,390。单图像素达到数亿级，任何全图一次性解析都可能造成内存溢出、请求超时或模型细节丢失。因此切块不是可选优化，而是核心能力。

### 7.2 切块接缝处重复与截断

切块必须有重叠区才能保证文字不被切断，但重叠区会导致文本重复。若重叠过小，容易丢字；若重叠过大，重复去除难度上升。因此需要坐标、文本相似度、段落语法和标题编号联合判定。

### 7.3 表格结构还原

采样表格 GT 以 HTML 表格为主，且包含大量空 `<td></td>`。表格得分基于结构而非单纯文本，行列错位、空格丢失、单元格合并误判都会严重影响 TEDS。表格类图片应优先以行列网格感知和 HTML 表格行级拼接为中心，而不是转成普通段落。

### 7.4 阅读顺序恢复

多栏排版、目录、跨页截图和表格块会让简单的“从上到下、从左到右”排序失效。需要把页面分块、列检测、标题编号、目录模式、表格边界与块级文本相似度结合起来。

### 7.5 金融领域文本细节

保险条款中存在条款号、注册号、备案号、金额、百分比、括注、释义引用、特殊符号与中英文混排。字级编辑距离会惩罚任何数字、标点、单位和符号错误，因此后处理不能过度“纠错”导致改错。

## 8. 验收标准

1. 输出 CSV 可被 `pandas.read_csv` 正确读取，列名完全为 `file_name`、`ground_truth`。
2. 输出文件覆盖测试集所有图片，且无重复文件名。
3. 每条 `ground_truth` 为非空 UTF-8 字符串。
4. HTML 表格标签成对闭合，Markdown 标题格式合法。
5. 运行日志可追溯每个文件的切块数、API 调用次数、失败重试次数和最终拼接策略。
6. 一键脚本可在干净环境中复现相同输出。
