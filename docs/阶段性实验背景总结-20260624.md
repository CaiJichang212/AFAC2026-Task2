## 2. 评分口径与问题拆解方式

### 2.1 离线评分口径

当前本地评估使用项目内离线 scorer，核心指标与赛题分析保持一致：

- `Text Edit`
- `Table TEDS`
- `Read Order Edit`
- `Overall = ((1 - Text Edit) * 100 + Table TEDS + (1 - Read Order Edit) * 100) / 3`

解读原则：

- `Text Edit` 越低越好，主要反映文本内容误差。
- `Read Order Edit` 越低越好，主要反映块顺序、段落顺序、结构顺序是否接近 GT。
- `Table TEDS` 越高越好，主要反映表格结构恢复质量。
- `Overall` 是综合指标，但在当前任务中通常会被最弱的一侧强烈拖累。

### 2.2 文档类型拆解

训练和 A 榜分析都显示，必须把样本拆成两类单独看：

- `long_strip`
- `table_page`

原因是这两类页面的失分机理完全不同：

- `long_strip` 的主要问题是阅读顺序和结构块顺序。
- `table_page` 的主要问题是表格结构恢复失败与 HTML 破损。

## 4. 本轮改造前已形成的核心诊断

- 真正失分点在 `Read Order Edit`，即阅读顺序、结构块顺序、接缝拼接顺序。

### 4.2 table 全量训练集历史结论

用训练集 table 的 `merged/*.md` 临时重建 CSV 后，全量 table 指标曾得到：

- `Overall: -0.75`
- `Text Edit: 0.6741`
- `Table TEDS: 13.86`

结论：

- table 页面几乎没有形成可靠的结构恢复能力。
- 当前系统对 table 的主要行为仍是切块结果串接，而不是按视觉行列关系重建真实表格。

### 4.3 已确认的根因假设

#### table 侧

- 主要使用固定二维网格切块后串接 Markdown。
- `TableMerger` 偏轻，主要做 BeautifulSoup 修补和相邻重复表头处理。
- `DedupMerger` 对 table 块保护较多，几乎不做有效的行级去重和续接。
- HTML 结构破损会直接拖垮 QC 与 `Table TEDS`。

#### long 侧

- 大量 chunk 是 `fixed_cut`。
- 空白带切线命中率低。
- 导致结构块被切坏、接缝不自然、阅读顺序不稳定。

- `table` 侧整体恢复能力依然很弱

### 8.3 当前最重要的结论

- 总分瓶颈几乎完全由 `table` 决定。
- 后续不应再把主要精力投入到 `long` 的文本补字。
- 仅靠 HTML 修补和简单 chunk 串接，无法把 table 分数拉到可竞争水平。
- 后续优化必须把重点从“修补输出”转到“重建结构”。

## 9. 对后续优化方案的直接约束

后续方案设计应默认接受以下事实：

### 9.1 long 侧优化方向

- 重点不是 OCR 文本准确率。
- 重点是块级排序、段落顺序、标题/正文结构连续性。
- 应优先考虑：
  - 更稳的 cutline 规划
  - 更少的 `fixed_cut`
  - 更强的 block-aware 顺序恢复
  - 更保守的接缝合并

### 9.2 table 侧优化方向

- 不能再把 table 视作“普通 markdown 片段拼接”问题。
- 必须把表格恢复看作结构重建问题。
- 方案至少需要覆盖：
  - 行级与列级对齐
  - 跨 chunk 表格续接
  - 表头继承与重复消解
  - 行级去重
  - HTML 闭合与异常结构隔离

### 9.3 工程稳定性方向

- table 路径的 CLI 收尾卡死必须单独治理。
- 即使核心结构算法未立即改善，工程链路也需要保证：
  - 全量实验能稳定收敛
  - 正式 `submission.csv` 能落盘
  - `qc/summary.json` 能可靠生成
  - 不依赖人工手工兜底

## 10. 作为下一轮方案输入时应直接引用的事实

后续写优化方案时，建议直接把以下事实作为前提：

1. 当前分支在 `long` 上基本稳定，但没有显著提升。
2. 当前分支在 `table` 上仍远未达到可提交水平。
3. A 榜历史低分与本地训练集复现出的 table 风险模式高度一致。
4. 当前最可靠的收益来源不是继续打磨 long 文本，而是重做 table 结构恢复。
5. 如果不先解决 table 结构问题，整体 `Overall` 很难接近 A 榜高分区间。
6. 如果不修复 table CLI 收尾问题，全量实验成本和复盘成本都会持续偏高。
